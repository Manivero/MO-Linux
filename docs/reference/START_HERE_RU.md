# Как запустить разработку с AI

## Что подготовлено

- `AI_MASTER_PROMPT.md` — постоянные правила для AI-агента: архитектура, ограничения, безопасная работа, требования к тестам и отчётам.
- `IMPLEMENTATION_ROADMAP.md` — полный план от инвентаризации оборудования до релиза.
- `PHASE_PROMPTS.md` — отдельные готовые задания для каждой фазы.
- `PROJECT_STATUS_TEMPLATE.md` — шаблон состояния проекта и журнала изменений.

Техническая документация написана на английском, чтобы её можно было сразу оставить в Git-репозитории и использовать с разными AI coding agents.

## Правильный порядок

1. Создай локальную папку проекта, например `MyLinux`.
2. Помести туда все файлы из этого комплекта.
3. Открой папку в Codex CLI, Gemini CLI, Claude Code, Hermes или другом агенте, который умеет читать и редактировать локальные файлы.
4. Передай агенту `AI_MASTER_PROMPT.md` и `IMPLEMENTATION_ROADMAP.md` как постоянный контекст проекта.
5. Затем отправь ему только задание Phase 0, приведённое ниже.
6. Проверь отчёт и изменения. Только после проверки разрешай Phase 1.

Не отправляй все фазы одним заданием. Иначе агент может начать собирать систему, пакетный менеджер, установщик и ядро одновременно, без проверяемой основы.

## Первое задание для AI — Phase 0

Скопируй агенту этот текст:

```text
Прочитай полностью AI_MASTER_PROMPT.md и IMPLEMENTATION_ROADMAP.md. Пока ничего не реализуй за пределами Phase 0.

Начни Phase 0: Product requirements and hardware discovery.

1. Безопасно изучи текущую папку проекта, Git-состояние и среду сборочного компьютера.
2. Отдели характеристики build host от характеристик старого ноутбука, на котором должна работать готовая ОС.
3. Если целевой ноутбук доступен, собери его характеристики read-only командами: модель, CPU, RAM, накопитель, GPU, Wi-Fi, аудио, BIOS/UEFI, аккумулятор и suspend/resume. Если ноутбука нет, не выдумывай характеристики — явно отметь, что требуется тестовое устройство.
4. Зафиксируй цели продукта, классы оборудования, функциональные требования, ограничения и открытые архитектурные решения.
5. Создай deliverables, перечисленные для Phase 0 в IMPLEMENTATION_ROADMAP.md.
6. Не устанавливай пакеты на host, не меняй разделы диска и настройки загрузки, не запускай сборку LFS, не создавай коммиты и не отправляй изменения в remote.
7. В конце обнови PROJECT_STATUS.md и IMPLEMENTATION_LOG.md, запусти безопасные проверки и выдай отчёт в формате PROJECT_STATUS / IMPLEMENTATION_LOG / REPORT.

Остановись после Phase 0. Не начинай Phase 1, пока я не проверю результат и не дам отдельное задание.
```

## Как принимать работу AI

Не принимай фазу только потому, что агент написал «готово». Проверяй:

- какие файлы реально изменены;
- какие команды реально запускались;
- какие тесты прошли, а какие не запускались;
- есть ли логи и измерения;
- выполнены ли критерии приёмки фазы;
- не изменил ли агент хост, разделы диска или посторонние файлы.

Сборка, запись ISO и установка на физический ноутбук — разные операции. Первые тесты загрузки и установщика должны выполняться на виртуальных дисках в QEMU.
