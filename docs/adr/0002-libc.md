# ADR-0002 — C library (libc)

- **Status:** Proposed (pending owner approval)
- **Date:** 2026-10-30
- **Phase origin:** Phase 0
- **Decision owner:** Project owner (§8 — affects compatibility with proprietary software)
- **Confidence:** Hypothesis — measured revisit only if Legacy ≤ 1 GB profile is added

## Context

§6 of Project Initiation v2 requires: «glibc vs musl — по совместимости с проприетарным ПО, драйверами и приложениями». The kit pre-selects glibc; this ADR performs the comparison.

The target user has old laptops and expects pre-built binaries (older Chrome / Chromium snap, electron apps, closed-source Wi-Fi firmware loaders, vendor printer drivers) to run without recompilation. §2 priority #4 is hardware compatibility; §2 #1 is update reliability (glibc is the foundation of every package).

## Options considered

| Option | Binary compatibility | Code size (idle RAM contribution) | ABI stability | License | Maintenance cost |
|---|---|---|---|---|---|
| **glibc** | excellent — most pre-built Linux binaries target it | larger (~2–4 MB shared libs) | long-term stable | LGPL 2.1+ | low — upstream + LFS default |
| **musl libc** | partial — static-binaries fine, dynamic binaries built against glibc need a loader shim | smaller (~400 KB) | stable | MIT | medium — must rebuild every pre-built binary |

## Decision

Adopt **glibc**. Pin to LFS 13.1-systemd version: **glibc 2.44** (verified 2026-10-30 from the LFS 13.1-systemd packages list — `https://ftpmirror.gnu.org/glibc/glibc-2.44.tar.xz`).

## Rationale

1. The target hardware class includes laptops with closed-source Wi-Fi drivers (Broadcom, Realtek legacy) and binary-blob firmware loaders. These are built against glibc and assume glibc's loader. Rebuilding them against musl is sometimes impossible (no source available).
2. Pre-built browsers and Electron apps from major ISVs target glibc. The project's UX priority (§2 #6) is "users can do basic tasks without terminal expertise" — that includes running a browser. musl would force users to build their own or use a tiny set of musl-rebuilt alternatives.
3. The RAM delta between glibc and musl is small relative to the rest of userspace (~2 MB out of ~150–300 MB idle on a Legacy profile with Xfce). Optimizing libc before measuring everything else in Phase 5 would be premature.
4. glibc is the LFS default; using musl would mean diverging from LFS 13.1-systemd for many packages, multiplying maintenance cost.

## Consequences

- Positive: maximal binary compatibility, minimal rebuild burden, LFS instructions unchanged.
- Negative: ~2 MB more RAM than musl. glibc's NSS plugin mechanism is more complex to audit.
- Risks: a future low-end Legacy sub-profile (≤1 GB) might tip the balance back to musl.

## Revisit triggers

- A sub-profile with target idle RAM ≤ 256 MB is added (would force every byte to count).
- musl becomes the only libc with a stable ABI for some critical target driver.

## Verification plan

- **Verified (build):** build glibc 2.44 per LFS 13.1-systemd instructions (Phase 2).
- **Verified (QEMU):** `ldd --version` reports 2.44; a pre-built x86_64 binary (e.g., a recent Firefox or a closed-source `broadcom-sta-dkms` blob) runs without loader errors (Phase 3 / Phase 4).
- A compatibility matrix entry for each closed-source driver is recorded in `HARDWARE_COMPATIBILITY.md` (Phase 4).
