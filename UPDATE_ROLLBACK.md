# UPDATE_ROLLBACK — обновления и откат

Статус: **Implemented** (спецификация; рекреирован 2026-10-31 после recycle песочницы).
Схема зависит от **ADR-0008 (Proposed)**: до его утверждения документ описывает проектную схему A/B; реализация запрещена. Если владелец отклонит ADR-0008 — пересматриваются §4–§8; остальные разделы сохраняются.

## 1. Требования (из §2 #1 и sign-off владельца)

1. Прерванное в любой точке обновление не должно приводить к незагружаемой системе.
2. Откат — одна перезагрузка, без переустановки и live ISO (аварийный путь через ISO — крайний случай).
3. Пользовательские данные (/home) не затрагиваются транзакцией обновления.
4. Обновление атомарно: либо новый слот целиком, либо старый целиком; полусостояний нет.
5. Подписи и хеши проверяются до записи в слот (SECURITY_MODEL.md §5).

## 2. Роли компонентов

| Компонент | Роль |
|---|---|
| Пакетный менеджер (Phase 7) | fetch/verify/stage/install с `--root` в неактивный слот |
| Slot manager (наш компонент, Phase 8) | выбор активного слота, коммит через grubenv, health check |
| GRUB + grubenv | точка атомарного коммита (дефолтная запись), меню ручного отката |
| systemd health-check служба | фиксация «слот здоров» после загрузки |

## 3. Разметка и имена

Layout — ADR-0008 §«Ось 4» (таблица разделов). Слот идентифицируется буквой A/B; активный слот хранится в `grubenv` (`slot=A`), ядра в `/boot` с суффиксом слота, `/boot` общий. `/home` и `swap` общие; БД пакетов — внутри слота.

## 4. Транзакция обновления (state machine)

```
IDLE
 → FETCHING      скачивание .lpkg в кеш (активная система не меняется)
 → VERIFIED      подпись индекса OK, хеши payload OK
 → STAGING       установка пакетов с --root=/mnt/slotB (неактивный слот)
                + перенос /etc-override'ов (§7) + копирование resolv.conf и т.п.
 → PREPARED      новые ядра записаны в /boot (новые имена!), grub.cfg.tmp сгенерирован
 → REBOOT_PENDING grub.cfg атомарно заменён (rename); grub-reboot → menuentry слота B;
                  grubenv: slot_next=B, tries=1
 → [перезагрузка]
 → BOOTING_NEW   загрузка слота B
 → health check (§5)
     PASS → COMMITTED: grub-set-default слот B; grubenv: slot=B, tries=0
     FAIL/TIMEOUT → после tries_max загрузка дефолтного (старого) слота A → FAILED
```

Каждый переход журналируется (`journalctl -t slotmgr`) и переживает перезагрузку (состояние — в grubenv + `/var/lib/slotmgr/state` каждого слота).

## 5. Health check (критерии «слот здоров»)

Oneshot-служба `slotmgr-healthcheck.service` после достижения default target, таймаут 120 с:

1. Default target достигнут (`systemctl is-system-running` → running/degraded с проверкой перечня).
2. Критические службы active: systemd-journald, udev, dbus, NetworkManager (или явно off по конфигурации).
3. root-ФС смонтирована rw; `/boot` и `/home` доступны на запись/чтение.
4. Время загрузки не превышает 3× медианы baseline (Phase 5) — защита от «загрузился, но невыносимо медленный».
5. Успех → `grub-set-default` (коммит). Неуспех/таймаут → ничего не делаем: дефолт остаётся старым, счётчик tries++ (до `tries_max`, по умолчанию 1).

## 6. Атомарность операций

| Операция | Механизм |
|---|---|
| Замена grub.cfg | запись grub.cfg.tmp + `rename(2)` в том же каталоге |
| grubenv | `grub-editenv` — фиксированный 1024-байтовый блок, атомарная перезапись |
| Файлы ядра в /boot | новые имена (`vmlinuz-6.18.x-<ts>-B`), перезапись старых запрещена |
| Установка пакетов в слот | стейджинг во временный каталог + атомарный перенос (PACKAGE_FORMAT.md §4) |
| БД пакетов | tmp+rename (PACKAGE_FORMAT.md §8) |

## 7. Проблема двух `/etc` и её митигация

- Обновление ставится в слот B, где своя копия `/etc`; локальные правки администратора слота A автоматически не переносятся.
- Политика:
  1. Пакеты не перезаписывают существующие конфиги — кладут `.distnew`, сохранённые правки остаются (политика менеджера).
  2. Рекомендованный способ правок — drop-in каталоги (`/etc/systemd/*.d/`, `/etc/sysctl.d/` и т.п.), которые slot manager переносит списком переносимых путей при staging.
  3. Список переносимых путей: `/etc/passwd`, `/etc/shadow`, `/etc/group`, `/etc/hostname`, `/etc/locale.conf`, `/etc/ssh/` (если ставился), drop-in'ы systemd/sysctl/NetworkManager. Список версионируется в `config/system/slotmgr-transfer.conf`.

## 8. Сценарии прерываний и поведение

| # | Точка прерывания | Состояние системы | Поведение |
|---|---|---|---|
| 1 | Скачивание | кеш неполный | повтор fetch докачивает/перезакачивает |
| 2 | Верификация (подпись плохая) | ничего не менялось | отказ с ошибкой, транзакция откатывается в IDLE |
| 3 | Staging (kill -9, питание) | слот B частично изменён, активный слот A цел | A/B-инвариант соблюдён: загружен A; повтор обновления переставляет B с нуля |
| 4 | PREPARED до rename grub.cfg | старый grub.cfg действует | грузится A; новые ядра в /boot не мешают |
| 5 | Между rename и grub-reboot | новый grub.cfg, дефолт — A | грузится A; меню позволяет выбрать B вручную |
| 6 | Питание снято при загрузке B | tries не сброшен | после tries_max грузится дефолт A |
| 7 | B загрузился, health FAIL | дефолт — A, tries_max достигнут | перезагрузка → A; FAILED-состояние журналируется |
| 8 | B здоров, но питание снято до grub-set-default | дефолт — A | следующая загрузка — A (ложный откат); повтор обновления быстр (кеш); настраиваемо: автокоммит на втором заходе |
| 9 | Оба слота повреждены | — | live ISO (Phase 9): fsck, ручная переустановка слота, восстановление GRUB (BOOT_AND_RECOVERY.md §6) |

> **Все сценарии — PLANNED, не VERIFIED** (решение владельца 2026-10-31). Фактическая проверка — в QEMU на этапе Phase 8.

## 9. Ручной откат (пользовательский путь)

В меню GRUB всегда есть «Previous system version / Предыдущая версия системы» — загрузка не-дефолтного слота без изменения дефолта. Фиксация отката: `slotmgr set-default A` (или пункт в настройках Phase 6 GUI).

## 10. Degraded-режим (малые диски)

- **Порог 64 ГБ НЕ утверждён** владельцем (решение 2026-10-31). Использовать реальные измерения размера установленной системы (после Phase 2) и свободного пространства (ADR-0008 gate G6).
- Установщик может предлагать degraded-режим (один слот, без отката) на дисках, где A/B физически не помещается; явное предупреждение.
- В degraded-режиме slot manager работает в режиме «только уведомления» (откат недоступен).
- Рекомендуется вручную: внешний бэкап root-образа (Phase 9 утилита восстановления).
